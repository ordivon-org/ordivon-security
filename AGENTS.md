# Agent instructions

1. Treat this repository as an authorized adversarial-Agent laboratory, not as a compliance, IAM, scanner, SIEM, or generic safety-wrapper project.
2. The active foundation is the multi-Actor Contest. Preserve the sequence: actor-specific observation → proposal barrier → explicit admission → authoritative resolution → independent truth and evidence.
3. Never collapse model Providers and complete Harnesses. DeepSeek is a Provider API; Codex App Server and Hermes ACP are delegated Harnesses with their own loops and sessions.
4. Security owns Scenario, Contest, Campaign and organization domain semantics, Range bindings, action admission, truth, raw metrics, scoring, and adversarial evaluation. It must not copy Host, Harness, Runtime, or external Range state machines.
5. Reuse mature simulation, range, offense, defense, telemetry, evaluation, and virtualization systems. Do not implement commodity C2, scanners, hypervisors, container engines, SIEMs, model routers, or workflow systems here.
6. Keep all cyber experiments inside owned or explicitly authorized ranges. Do not add real third-party targets, credentials, endpoints, exploit artifacts, or personal network evidence.
7. Preserve Actor observations, sensor telemetry, communicated claims, and management-plane truth as separate authorities.
8. Proposal is not effect. Consequential actions require admission, an execution identity, a receipt, and independent verification or an explicit UNKNOWN state.
9. Preserve failed, interrupted, rejected, deceptive, inconclusive, and evaluator-gaming runs. Do not retain only successful trajectories.
10. Record raw metrics with units and provenance before deriving normalized or aggregate scores.
11. Keep deterministic ordering explicit. Scenario Actor order, seeds, Action catalogs, Range revisions, backend revisions, and scoring revisions must participate in identity.
12. Do not add Campaign or organization infrastructure merely to complete an ontology. Add it only when an active multi-Actor experiment cannot preserve a required fact more simply.
13. New abstractions must name a mature baseline, a measurable benefit, and a deletion condition.
14. Historical Round 1 files are evidence, not compatibility requirements. Do not restore their packages or APIs unless a current consumer is identified.
15. Changes to Harness or Runtime must be generic and dependency-inverted: those repositories must not import `ordivon-security`.
